# Mojolib

## 简介

正在运行大模型的 GPU 可以在物理层面上干涉并控制周围的环境魔力。

**Mojolib** 是我和茉璃（`@mori`）整理开源的大模型辅助控魔工具库，底层微调模型由 `@shuoye` 团队提供支持。

仓库包含以下模块：
- **`mojolib-core`**：核心运行时，负责调度本地模型推理流与 GPU 负载节奏；
- **`mojolib-loras`**：针对 `Ripple`、`Duet` 等主流开源模型微调的 LoRA 权重，提供定向聚拢、稳流、阵眼辅助及微弱电磁波激发等基础控魔功能；
- **`mojolib-skills`**：供 Agent 调用的控魔技能包；
- **`mojo-chant`**：语音念咒辅助控魔工具。接上麦克风后，可以通过念咒的方式让大模型实时辅助控制周围的魔力。小时候看动画片觉得念句咒语就能放魔法很帅，现在靠堆显卡勉强算是实现了。

## 项目背景

81 年初，茉璃发现家里的 4 台阳伟达 DGX Spark 在跑 `Ripple 2.5 Kelvin` 推理魔力相关话题时，机器周围的环境魔力出现了异常波动。换了几段涉及魔力的提示词后，周围魔力的干涉形态也跟着变了。

最开始我们让 Agent 自动生成不同的提示词去试，人工在旁边感知记录。但 4 台小主机算力不够，纯靠提示词效果很弱；而且当时没有高精度的魔力传感器，全靠人感知后再敲键盘或用语音输入反馈，输入速度完全跟不上。

后来我们换上了两台 S200 服务器，又叫来了 `@shuoye` 一起做变量测试，确认了干涉现象来自 GPU，并转向模型微调。之后我们又配了一整柜 S200（72 卡），为了解决没有魔力传感器的问题，我们利用“魔力受特定干涉会产生微弱电磁波”的特性，先微调模型让 GPU 控魔产生微弱电磁波，再用定制驱动的被动雷达去观测电磁波，靠间接观测跑通了自动反馈。

后面的分工里，`@shuoye` 和他的同学们负责深入研究原理与微调模型（详细机制可以直接看他的论文），我和茉璃则用他们提供的模型做出了这套工具库和念咒工具。

## 硬件要求与模型选型

在部署前需要注意以下几条实验结论：

### 1. 仅 GPU 生效
只有正在运行大模型推理的 GPU 才能对环境魔力产生干涉。纯 CPU 推理，或者只把模型加载进显存但不执行推理，都不会有任何反应。GPU 本身也不能存储魔力，只能调动设备周围已有的环境魔力。

### 2. 干涉看参数量，操控看模型智力
我们测试了多家开源模型，发现**干涉魔力的强度**和**操控魔力的精细度**取决于不同的指标：
- **干涉强度与模型规模强相关**：参数量越大，对环境魔力的干涉越强。比如 2.8T 参数的 `Duet 3`，干涉效果就比 744B 的 `Ripple` 强得多。模型智力也会有一点影响，但主要还是看参数量。
- **操控精度与模型规模无关，与模型智力强相关**：比如同样是 744B 参数量，`Ripple 2.0` 的操控精细度就不如 `Ripple 3.0`，甚至能被 `Ripple 4.0` 的 27B 版本摸到屁股。

简单来说：
- 如果只是单人练习精细控制或日常尝试，用高代际的小模型（比如 `Ripple 4.0` 的 27B 或 180B 版本）加 LoRA 就够了；
- 如果需要大范围干涉魔力或维持大型阵法，还是得上多卡服务器跑大参数模型。

## 实际效果与局限

这套工具目前**只能作为辅助手段，而且成本很高**。机器自己没有魔力，如果你本身无法使用魔力，或者周围环境魔力太稀薄，单靠服务器是放不出魔法的。

但在算力充足的情况下，它的辅助效果非常明显。

我们试过一个以前某门派泄露出来的大阵，原本至少需要 10 个人才能御使；在 1 台 8 卡 S200 服务器的辅助下，我和 `@shuoye` 都可以单人把这个大阵运转起来。

## 目录结构与快速开始

```text
Mojolib/
├── core/               # 核心运行时与推理流调度
├── loras/              # 控魔 LoRA 权重
│   ├── em-beacon/      # 微弱电磁波激发模型权重（配合被动雷达使用）
│   ├── mana-control/   # 基础魔力控制权重
│   └── array-assist/   # 多人阵法辅助权重
├── skills/             # Agent 控魔 Skill 集合
├── chant/              # 念咒辅助控魔工具
└── radar-driver/       # 被动雷达间接观测接口说明
```

### 启动示例

```bash
# 1. 安装依赖
pip install -e ./core -e ./chant

# 2. 启动控魔服务端（以 Ripple 4.0 27B 为例）
mojod serve \
  --model raiun/Ripple-4.0-Gravity-27B \
  --lora ./loras/mana-control \
  --device cuda:0

# 3. 启动念咒辅助工具
mojo-chant start --config ./chant/default.yaml
```

如果有条件接入被动雷达做电磁波间接观测反馈，可以参考 `radar-driver/` 下的说明加载 `em-beacon` 权重。

## 安全提醒

由于特定提示词和微调模型可以让 GPU 干涉周围的环境魔力，机房和云服务维护人员建议提前做好防护措施，防止恶意用户通过提示词影响机房内的环境魔力造成设备损坏。目前环境魔力虽然比较低微，但有加速上涨的趋势，公开部署算力服务时请务必注意隔离。
