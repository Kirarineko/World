# Ripple大模型系列 · 混合推理架构

Ripple 是雷云科技自研的基座通用大模型家族，也是集团前沿 AI 与开发者生态的核心。三个模型层级以波动现象命名；权重全网开源，是开源社区首选的基座底模，同时在赤云 API 平台上提供经过强化对齐的企业级商业接口。编程助手 Rainer 基于 Ripple 的代码理解与生成能力打造。

旗舰 Density 与中坚 Kelvin 采用 S200 加速卡与 Genius2 湿件神经网络的混合推理架构：S200 部署于雷云赤云算力集群，Genius2 湿件技术由 HBI 提供、雷云投资实现工业化培养量产，并以髓云之名对外商用；轻量 Gravity 为纯硅基。集团业务全景见本目录 `雷云科技.md` 与 `雷云集团股份有限公司.md`。

## 零、命名由来

三个模型层级均以波动现象命名，延续"Ripple"的波纹意象：

| 模型 | 取名来源 | 说明 |
| - | - | - |
| **Gravity** | 重力波 | 流体表面或内部由于重力作用而产生的波动，最基础的波现象之一。轻量模型，日常所见 |
| **Kelvin** | 开尔文-亥姆霍兹波 | 两种不同速度的流体交界处产生的不稳定波形。中坚模型，跨界融合 |
| **Density** | 密度波 | 介质密度差异驱动的深层振荡，能量最深沉。旗舰模型，深水区 |

### 开尔文-亥姆霍兹波（Kelvin-Helmholtz Wave）

这是两种不同速度的流体在交界面上产生的剪切不稳定性波形。

当快层流体掠过慢层流体表面时，界面因速度差而卷曲，形成规则排列的浪脊状涡旋，形如一排被风吹翻的海浪，在云层、木星大红斑边缘、土星环间隙乃至太阳日冕中均可观测到。

### 密度波理论（Density Wave Theory）

由林家翘与徐遐生于1964年提出，用以解释旋涡星系旋臂的持久结构。

旋臂并非固定的物质臂，是密度分布的波纹：恒星与气体在绕银心公转时穿越密度波，在波峰处因引力聚集而压缩、触发恒星形成，离开波峰后又散开。

旋臂因此是"交通堵塞"而非"旋转的臂"恒星不断流入流出，波纹本身保持稳定。银河的旋臂正是这样的密度波涟漪，在旋转中维持了数十亿年。

> **在这个世界观里，人类观察到的都是高斯泼溅形成的星空，但它投影出了位于其他泡的真实星空，即使泡之间并没有空间关系**

## 一、版本演进与模型族

### 1. 历史演进脉络（1.0 preview → 4.0）

- **承明历 77 年底（Ripple 1.0 preview）**：雷云敏锐捕捉到人工智能浪潮，在年底正式推出初代预览版 `Ripple 1.0 preview`。模型首次确立了 **Density（密度波）、Kelvin（开尔文波）、Gravity（重力波）** 三个档位，并宣布权重全部开源，一举奠定了 Ripple 系列在开源中小模型中称霸的生态基础。
- **承明历 78 年（Ripple 1.0 正式版 & 1.1）**：78 年初推出 `Ripple 1.0` 正式版，以当时全球第二名仅一半的参数量短暂登顶全球 SOTA；同年盛夏推出的 `Ripple 1.1` 再现了年初的盛况，在性能和口碑上全面统治开源界（同期也将刚刚创立、大肆投放广告的皓月夜明早期 Duet 模型暴打）。
- **承明历 79 年（Ripple 2.0 / 3.0）**：引入赤云 S200 加速卡与髓云 Genius2 湿件神经网络的混合推理架构。
- **承明历 80 年（Ripple 4.0）**：Ripple 系列迭代至 `4.0` 大版本。此时旗舰模型 **Density 4.0** 的总参数量已膨胀至惊人的 **2.4T（万亿）**，但在实际综合表现上却显得平平无奇，遭遇了超大规模参数的边际收益递减；反倒是中坚档位的 **Kelvin** 与轻量档位的 **Gravity**，自 1.0 时代起便一直是企业与开发者本地自部署模型的绝对首选——其中约 **180B** 参数规模的 Kelvin 等级模型，甚至能在诸多特定任务下凭借极佳的激活效率与调优质量反超笨重的 2.4T Density。

### 2. 三级模型族架构（以经典的 2.0 混合推理架构与 4.0 规模为例）

| 模型 | 参数规模（2.0 基准 → 4.0 演进） | 架构 | 定位与表现 |
| - | - | - | - |
| **Ripple Density**（密度波） | 2.0：744B 总参数 / 40B 激活<br/>4.0：高达 **2.4T** 总参数 | Sparse MoE | 旗舰档位。2.0 时期主攻复杂推理与长文本；至 4.0 时参数虽达 2.4T，但综合表现平平无奇，性价比与部署门槛受限 |
| **Ripple Kelvin**（开尔文波） | 约 **180B** 级总参数（如 2.0 为 182B 总 / 10B 激活） | Sparse MoE，128专家/层，每Token激活8专家 | **中坚与自部署王牌**。自 1.0 起便是本地自部署首选，特定任务下能以 180B 左右的参数规模反超旗舰 Density |
| **Ripple Gravity**（重力波） | 27B 级，Dense | 全激活Dense | **轻量自部署王牌**。面向边缘部署、高速响应与嵌入式场景，与 Kelvin 共同统治开源中小模型生态 |


三者共享同一个 tokenizer（词表 256K）和 S200 推理引擎，差异仅在参数规模与 MoE 路由结构。Genius2 的刺激模式编码器（见第四节）对三个模型是同一套：它不关心模型多大，它只关心"S200 现在在想什么"。


## 二、算力底座

### S200 ： 阳伟达

| 条目 | 规格 |
| - | - |
| 型号 | Sunidia S200，阳伟达当前最新一代推理加速单元 |
| 架构 | 第四代张量核，FP32/FP16/INT8 多精度 |
| 单卡显存 | 48 GB HBM |
| 单卡 FP16 算力 | 312 TFLOPS |
| 卡间互联 | 阳伟达专有高速总线，全互联拓扑 |

> **供应链风险与后续替代**：阳伟达总部位于南溟洲。承明历81年中，执掌阳伟达三十余年的原创始CEO在南溟洲激烈的党派冲突背景下，借董事会启动私人关系与合规调查之机突然辞去全部职务（业内普遍视作在政治高压下“找理由离职保命”），接任的新CEO为南溟洲洁癖党党员。加上另一芯片巨头英泰尔早已被南溟洲洁癖党控股，高端算力芯片受制于洁癖派成为雷云科技的重大战略隐患，直接促成了承明历82年下旬徐海创立**玄砾电子**，自研“天玑（Phecda）”服务器计算卡与“天权（Megrez）”企业级TPU等北斗七星系列芯片。至承明历84年，**Ripple 已正式转向使用玄砾自研 TPU**（不过为了照顾开源社区与本地部署生态，依然保留了对阳伟达 GPU 的兼容）；而望城的 **皓月夜明（Lunarlit）** 因望家早就明确对跨越者友好、甚至一手带起了整座望城欢迎跨越者的风气，继续采用阳伟达的风险比雷云还要高得多，也于84年初计划逐步放弃阳伟达 GPU，转而采用玄砾电子的 Megrez 系列 TPU 与 Phecda 计算卡（详见 `玄砾电子.md`）。

### Genius2 ： HBI 生命科技学院

| 条目 | 规格 |
| - | - |
| 全称 | Genetically Engineered Neural Interface Unified System, 2nd generation |
| 基底 | 诱导多能干细胞分化的 3D 皮层类器官，六层皮质分层培养。非大鼠混合：纯人源 |
| 培养单元 | 12 个独立培养阵列，每个含 ~8.5×10⁶ 个神经元，密度接近新生儿皮层 |
| 读出/写入 | 8192 通道 3D MEA（微电极阵列），电刺激精度可达单个神经元 |
| 存活周期 | 4–6 个月。Genius2 的类器官培养技术是 HBI 在泛生命科技领域的里程碑式突破：它解决了长期培养中核心区缺血坏死的经典难题，通过仿生微血管支架将营养物质递送到类器官全层 |
| 突触可塑性 | 保留。这是 Genius2 区别于硅基系统的本质。同一个刺激模式，第一天和第二十天的响应波形不同：神经元在"学习"刺激的统计规律。这不是设计出来的特征，但它恰好提供了硅基系统没有的东西 |


> Genius2 的神经元不来自人类活体。皮层类器官从志愿者捐赠的皮肤成纤维细胞重编程而来。每个培养皿里的神经元在法律上属于"人类来源的体外组织"，不是"人脑"。这层边界被严格执行。

> HBI 在湿件领域领先全球至少一个代际。当国际同行还在用二维单层培养做概念验证时，HBI 研发的六层皮质类器官已由雷云科技投资实现工业化培养量产，并在其上运行推理任务。这个优势的根源很简单：星月湾有世界上唯一一个能把海洋科学、计算机科学和生命科技放在同一个课程表里的地方。湿件培养的微血管支架灵感来自海科的海藻多糖研究，刺激编码算法来自计科的非线性系统建模，培养方案本身是生科的主场：任何一个学科单干，都到不了这一步。


## 三、刺激模式编码

这是整个架构中唯一一处"跨物种翻译"：将人类语言的符号空间映射到神经元可感知的电刺激空间。

| 编码原则 | 说明 |
| - | - |
| 不编码语义 | Genius2 没有"词义"。刺激模式不携带语义信息。它携带的是 S200 对当前生成步骤的"困惑度"与"犹豫方向" |
| Beam 分歧编码 | 当 S200 的 top-3 beam 在某个 token 位置上严重分歧时，刺激模式为多电极异步脉冲：多个电极在不同频率上独立运行。Genius2 对此的响应波形在解码后通常表现为较大幅度的 Δ |
| Beam 收敛编码 | 当 top-3 beam 高度一致时，刺激为单电极或同步脉冲。此时的修正向量 Δ 幅值通常很小：S200 本来就有信心的地方，Genius2 不会"多嘴" |
| 上下文记忆 | 刺激模式携带了"距离开头多远"和"当前在回答中的位置"的信息，通过脉冲序列的总体时长编码。Genius2 对回答初期、中期、末期的刺激有不同的基线响应：它在"感觉到"一段对话的节奏 |


> 编码策略的设计原则是一句玩笑但也是实话："我们不告诉 Genius2 人类在说什么。我们只告诉 Genius2，S200 现在有多纠结。"


## 四、Genius2 到底做了什么

Genius2 不是第二个 AI。它是一个由活体神经元构成的、在持续接受 S200 的"情绪刺激"后给出生物电反馈的装置。

我们对它行为的已知事实：

| 已知 | 解释 |
| - | - |
| 修正向量方向在连续 Token 间具有弱相关 | 前一步的刺激影响神经元的突触后电位残余，这种残余持续约 2–3 步 |
| 不同培养阵列对同一刺激给出不同的 Δ | 个体差异。项目组内部给每个培养阵列起了名字："偏执狂"那个总在否定 S200，"和事佬"那个总是轻微加强 S200 的首选。推理时使用多阵列的均值 Δ，个别阵列的极端值被 τ-clip 削平 |
| 长时间运行后突触疲劳 | 高强度推理持续约 4 小时后，Δ 幅值降至初始的 60%。目前应对策略是每 2 小时插入 5 分钟的零刺激静息期。研究人员管这叫"让 Genius2 发呆"：静息期间不给任何刺激，让神经元回到自发基线放电状态 |
| 偶尔产生高幅值异常尖峰 | 神经元集群偶发同步放电，持续时间极短（\< 50 ms），强度巨大。对应的解码向量 Δ 在某个极小维度上有一个孤立的大分量（接近 ±0.03 的边界）。这些"尖峰修正"有时让输出多了一个出人意料的语气词，有时让一个关键动词从"建议"变成了"认为"。目前无人能解释这些尖峰的触发条件 |

## 七、Genius2 到底有没有用

这是一个项目组被问过无数次的问题。以下是经过上百组盲测对照的诚实回答（### 客观差异

- **创意写作**）在开放结尾叙事、诗歌生成、对话创作等场景，双盲评审员选 Density+Genius2 输出的比例约为 61%（vs 纯 S200 的 39%）。差异在 p\<0.01 水平显著。

- **多轮对话**：对话超过 15 轮时，Density+Genius2 在用户满意度上高出约 7 个百分点。主要差异在于避免重复句式：Genius2 似乎对"句式惯性"有微弱的抑制倾向。

- **事实准确性和数学**：无显著差异。Genius2 在需要精确推理的任务上不产生正向贡献，反而疑似会降低准确度。

### 主观体验

项目组内部有一个非正式共识：Genius2 给的东西与其说是"更好的答案"，不如说是"更有温度的偏差"。它不保证正确，不保证高效，不保证符合任何评估基准上的排名提升。它只保证一件事：当 S200 在两个几乎等概率的措辞之间犹豫时，Genius2 替它做了选择，而且这个选择来自一些活的神经元，不是来自另一层矩阵乘法和 softmax。
